# manual_quant —《经营未来》v5.0 手册量化回测框架

把手册的规则（R-01~R-41）与验证协议（V-01~V-10）落成可回测、可验证的代码。

- **接口契约**：`SPEC.md`（唯一权威；所有签名、字段名、常量以它为准，本框架不得偏离）。
- **规则原文**：规则编号（R-01~R-41）与阈值逐条来自个人整理的《经营未来》v5.0 手册（附录五规则总表、
  附录六验证协议），代码注释里标注了对应行号（如 `L166`）。**该手册的章节提取文本未随仓库发布**
  （版权考虑），因此仓库中的 `spec/XX-*.md` 引用指的是本地提取件；外部读者可直接读代码注释里的行号定位。
- **设计底线**：证据分级闸门（C/D 级不得单独构成买入依据）、观测口径以风险指标优先、样本 <20 笔视为噪声、
  缺失数据只标注「数据不足」不臆造。出处见 `SPEC.md` 第 0 节。

## 0. 数据准备（仓库不含行情数据）

本仓库**只含代码**，回测用的行情与财报数据需自备（数据再分发有合规问题，故未附带）。框架按
`MQ_DATA_DIR` 找到数据目录，默认取 `../six_layer_backtest/data/parquet`。需要的三份文件：

| 文件 | 内容 | 关键列 |
|---|---|---|
| `daily_all.parquet` | A 股个股前复权日线（约 4900 只，2016 起） | `code, date, open, close, volume` |
| `yjbb.parquet` | 季度业绩报表（44 期快照，含财务字段） | `股票代码, 每股收益, 营业总收入-营业总收入, 净利润-净利润, 净资产收益率, 销售毛利率, 最新公告日期, report_period` |
| `index.parquet` | 沪深300 指数日线 | `date, open, high, low, close, volume` |

```bash
# 指向你自己的数据目录
export MQ_DATA_DIR=/path/to/parquet
python3 run.py check      # 会列出哪些数据可用、哪些登记为「数据不足」
```

**富字段业绩报表**（`yjbb.parquet`，含毛利率/净利率/ROE 等列）是价值卡的门槛来源，按以下顺序探测：

1. `$MQ_YJBB_RICH` 直接指定；
2. `<MQ_DATA_DIR>/yjbb_rich.parquet`；
3. 原布局 `<DATA_DIR 的上两级>/backtest/data/parquet/yjbb.parquet`；
4. 退回 `<MQ_DATA_DIR>/yjbb.parquet`（若只有瘦字段版，财务门槛会登记「缺字段」而不是报错）。

数据缺失时框架**不会崩**：相关规则登记者为「数据不足」并在报告里标注。可用 akshare 自行抓取
（腾讯／东方财富／新浪三源，注意限流）；业绩报表用 `ak.stock_yjbb_em(date=报告期)`。

## 2. 七步法流水线（`core/seven_step.py`）

手册第〇章的决策顺序（`L125—127`）在代码里就是**逐层否决**：任一步返回 `passed=False` 即终止，并把
「被哪一步、哪条规则、什么证据否决」记进结果。每步签名固定 `(passed, reason, evidence)`，
`evidence` 内必带 `rule_ids`（供记录表与闸门检查）。

| 步 | 函数 | 检查内容 | 规则／行号 |
|---|---|---|---|
| 1 | `step1_capital_allowed` | 杠杆倍数=1、先还高息债务、应急金 ≥3 个月、资金 3 年内不用、不孤注一掷 | R-01/R-02/R-03/R-08，`L131—134/186/275/292` |
| 2 | `step2_strategy_selected` | 三套打法先选一套、不中途换逻辑、理由不跨策略；个股须过进阶路径前置 | R-07/R-17，`L137—145/179/226` |
| 3 | `step3_logic_holds` | 逻辑写成 2—3 条可证伪陈述；价值流过巴菲特财务门槛；趋势流须趋势确认；指数流阈值须先校准 | R-05/R-39/R-34，`L151/395/396`、`L155/254` |
| 4 | `step4_valuation_reasonable` | R-27 安全边际三档（≥30% 一般／≥33% 门槛／≥50% 经典）；无内在价值数据则**明确降级为定性** | R-27，`L156/289—291` |
| 5 | `step5_position_size` | 归零口径单标的 ≤5%、费雪分类上限（取更严）、持仓数 3—10、禁止摊平；趋势仓首笔 ≤1/5 与单笔风险 1%—2% | R-04/R-14/R-16/R-35/R-37/R-38 |
| 6 | `step6_buy_trigger` | 三条件同时满足（第三步+第四步+第五步）＋风险否决清单＋`rules.gate()` 证据闸门；依据必须记账 | `L166—168`，SPEC §0 |
| 7 | `step7_exit_plan` | 买入前先写退出条件；价值仓三个卖出理由＋三年守则；趋势仓止损 1%；指数仓估值卖出/再平衡 ±5pp | R-05/R-28/R-32/R-36/R-13，`L166/172—173` |

用法（`ctx` 为 `dict`，键见各步函数；`run_pipeline` 会把已完成步骤写入 `ctx["_results"]`，供第六步复核）：

```python
from core.seven_step import run_pipeline, steps_meta
r = run_pipeline({
    "code": "600519", "strategy": "value", "report_period": "20231231",
    "horizon_years": 10, "emergency_fund_months": 6, "high_interest_debt": False, "leverage": 1.0,
    "basic_path_months": 8, "weekly_research_time": True, "read_method_ch2": True,
    "falsifiable_conditions": ["营收增速转负", "毛利率跌破 30%"],
    "equity": 100000.0, "price": 10.0, "planned_weight": 0.05, "n_positions": 3,
    "margin_of_safety": 0.40, "rule_ids": ["R-04"], "exit_conditions": ["逻辑变了即卖"],
    "sell_reasons": ["公司变了"], "hold_plan_years": 5,
})
r["passed"], r["stopped_at"], r["rule_ids"]   # False/None + 命中规则清单；steps 为逐步记账
```

引用本模块时**不要在 import 阶段做重活**：`config`/`rules`/`data.loader`/`core.risk_budget` 全部在函数内惰性导入，
所以模块可被单独 import 而不会读 989 万行 parquet。

## 3. 如何运行

```bash
# 数据可用性 + 规则闸门 + 七步法骨架自检
python3 run.py check

# 策略回测（信号 → engine → stats，按 SPEC §0 观测口径排序输出）
python3 run.py value
python3 run.py trend

# 长期配置与定投（月度金额必须显式给出，不臆造）
python3 run.py allocation --income 20000 --expense 12000     # (收入−支出)×50%，L208
python3 run.py allocation --monthly 5000

# 六维协议 → 判定 → 记录表
python3 run.py protocol --strategy value --start 2016-01-01 --end 2026-09-30
python3 run.py protocol --strategy all

# 全流程
python3 run.py all
```

- 退出码：`0` 通过／`1` 执行失败／`2` 依赖模块未就绪或缺必填参数（例如 `strategies/` 尚未落地）。
- 环境变量：`MQ_DATA_DIR`、`MQ_OUT_DIR`（路径覆盖）、`MQ_OFFLINE=1`（禁网，缺数据只标注「数据不足」）。
- 单模块自证：每个模块自带 `if __name__ == "__main__":` 冒烟测试，例如 `python3 core/seven_step.py`（本模块 <1 秒）、`python3 run.py check`。
- `check` 末尾的**数据缺口清单动态读自 `data.extra.availability()`**（分「可用／仅离线不可用／无法获取」三类），
  不写死任何缺口名——联网、离线、缓存三种情形取到的项不同（第 5 节）。
- 产物统一写 `output/`，文件名 ASCII：`verification_records.csv`（⑩ 记录表）、`data_availability.md`（② 数据可用性）；
  外部数据缓存落 `data/extra/*.parquet`（`MQ_EXTRA_CACHE_DIR` 可覆盖）。

指标输出顺序固定为 **最大回撤 → 波动 → 换手率 → 资金占用 → 策略失效期 → 收益率**（`SPEC.md` 第 0 节观测口径优先级，
原文行 2131）；`收益率` 只排最后。

## 4. 字段与单位口径（百分数／小数，别混用）

- **比率字段一律百分数**：`data/loader.py`（`strategies/value_card.py` 同口径）的 `net_margin`＝净利润 ÷ 营收 × 100、
  `gross_margin`（源列「销售毛利率」）、`roe`、`rev_yoy`、`profit_yoy` 都是**百分数**，净利率 5% 写作 `5.0` 而不是 `0.05`；
  财务门槛阈值同单位（毛利率 ≥ `40.0`、净利率 > `20.0`、ROE > `0.0`，`spec/04` L1364）。
- **唯一的小数口径是盈利收益率**：`data/extra.earnings_yield()` 默认返回 1/PE 的小数（`0.074` = 7.4%，SPEC §3-② 字面）；
  与 V-01／R-18／R-19 的 10%／6.4% 三档直接比较时用 `earnings_yield(pct=True)`。
  `try_fetch_bond_yield()` 的 `yield_10y` 是百分数（`1.68` = 1.68%）。
- **权重与风险比例一律小数**：`core/engine.py` 的 `weight`、`core/risk_budget.py` 的 `stop_pct`／`risk_pct` 用小数
  （`0.05` = 5%；`config.STOP_LOSS_PCT=0.01` = 1%）；`risk_budget.stress_test(shocks)` 另容错接受 `-40` 这种百分数写法。
- **`stats` 也是小数比例**：`总收益`／`年化`／`最大回撤`／`波动`／`换手率`／`资金占用`／`胜率` 均为小数
  （`max_drawdown=0.2009` 即 20.09%，`总收益=1.2354` 即 +123.54%）；`策略失效期` 是交易日天数。

## 5. 已知数据缺口与不可验证项

**权威清单是 `output/data_availability.md`（由 `data/extra.py` 的 `availability()` 产出，`run.py check` 末尾直读同一份登记）**；
本节按它的口径分三类整理，若两者不一致，以该文件为准并回改本文件。取数结果随**联网／磁盘缓存（`data/extra/*.parquet`）／
`MQ_OFFLINE`** 变化，故不要把本表当常量抄进代码——`run.py check` 的缺口清单是动态读的。

### 5.1 联网可用（实测本机可取；离线命中磁盘缓存时仍可用）

| 数据项 | 来源 | 规模／频率 | 覆盖区间 | 支撑的规则／协议 |
|---|---|---|---|---|
| 指数 PE（沪深300） | 乐咕乐股 `stock_index_pe_lg`（备选 中证指数官网） | 259 行，月频，整体法加权 TTM | 2005-04-29～2026-10-09 | R-18/R-19/R-20、V-01（阈值 10%／6.4%，敏感性 ±2pp） |
| 盈利收益率 E/P | 同源 1/PE | 259 行，月频 | 同上 | R-18/R-19/R-24、V-01（比较时用 `pct=True` 口径） |
| 10 年期国债收益率 | 东财 `bond_zh_us_rate`（备选 中国债券信息网） | 4189 行，日频 | 2010-01-04～2026-10-10 | R-21/R-22 债基选择、n 放大器与阈值校准公式（定投线 ≈ max(2×当期利率, 6%)、卖出线 ≈ 当期利率＋2.5%~3%，`spec/07` ②）、V-02 |
| 债券指数（债券腿） | 新浪 `stock_zh_index_daily`（备选 中债财富指数、腾讯） | 5768 行，日频，上证国债指数 sh000012 | 2003-01-02～2026-10-09 | R-09/R-13 股债 25%—75% 与 ±5pp 再平衡、六维② 60/40、V-02/V-03 |

**债券腿口径（引用时必须一并写出）**：拿到的是**上证国债指数 sh000012**（国债／中债现券指数），**≠ 债券基金指数**——
不含债基申赎与管理费，也不含金融债、可转债、同业存单等持仓。`spec/07` ② 允许债券端用「债券基金指数或国债代表资产」，
故可用于 R-13 与六维② 60/40；但 `spec/09` ② V-02 的字面口径只算**部分满足**，属**降级替代**，须在结果与记录表标注
（备选源「中债-新综合财富指数（总值）」含票息再投资、更接近债基净值口径，仅在主源失败时启用）。

### 5.2 仅离线不可用（`MQ_OFFLINE=1` 且无本地缓存）——不是「数据不存在」

5.1 的四项在离线且无缓存时登记为「数据不足：MQ_OFFLINE=1 且无本地缓存 xxx.parquet」（SPEC §4 不联网）。
联网成功抓取一次后 parquet 落盘 `data/extra/`，此后离线**命中缓存仍然可用**；当前缓存覆盖 `index_pe.parquet`、
`bond_yield.parquet`、`bond_index.parquet`（实测 `MQ_OFFLINE=1 python3 run.py check` 四项仍为可用）。
所以看到这些项「数据不足」先看 note：写 `MQ_OFFLINE` 的是没联网，不代表取不到。

### 5.3 真正无法获取（联网也取不到，只能标注「数据不足」）

| 缺口 | 受影响的规则／协议 | 后果 |
|---|---|---|
| 股息率（无长期序列：中证指数官网接口仅约 20 个交易日） | R-20 博格公式、R-26 分红再投、V-08/V-10 | 博格三项无法同时判定；分红口径不可回测 |
| 资产负债表科目（货币资金/有息负债/其他应收/资本开支等） | R-33 价格 ≤ 净流动资产 2/3、R-30 造假嫌疑排雷（清单 G 存贷双高）、债券覆盖倍数与清算价值折扣 | 深度价值与排雷类规则不可回测 |
| 通胀/CPI 序列 | R-25 年取 ≤4%（需 CPI ＋长期股债组合序列）、V-05 实际取用率的中国样本自测（`spec/09` ② 行 2141） | 取用率只能按名义口径；实际取用率与「72 ÷ 通胀率」不可自测 |
| 美股数据（行情＋规模/价值因子） | R-11 持有期→权益比例表复现、R-31 美式语境、V-04 | 持有期→权益比例只能按手册给的两端点插值（5 年 25%、30 年 68%） |

### 5.4 非外部接口类缺口（本机数据边界内缺，代码按降级处理）

| 缺口 | 受影响的规则 | 降级方式 |
|---|---|---|
| 内在价值／DCF 输入项（自由现金流、折现率、增长率） | R-27 安全边际三档 | 降级为定性判断（`step4` 保留 `downgraded="定性"` 标记） |

### 5.5 纯定性／不可回测项

不建代码，仅在记录表里标注：R-05/R-06/R-07/R-08/R-39/R-40/R-41 属程序性约束；
`spec/09` ③ 明示 V-09 趋势规则「不适合投入回测资源——执行偏差主导结果」；诊断五归因中的「执行偏差」「逻辑失效」
与样本独立性判断无量化阈值；规则变更原因、状态链人工裁定属文本/审批动作。这些不进 `stats`，由 `validate/judge.py`
的判定与记录表承接。

### 5.6 已知问题

- **R-36 的 1% 止损在 A 股 100 股整手 + 10 万本金下会大量拒单。** 机制：R-35 规定首笔 ≤ 计划额度的 1/5，
  而计划额度 = min(R-04 归零口径 5%, R-38 风险预算反推 1.5%÷1% = 150%) = 5%，故首笔目标权重只有 1%；
  10 万 × 1% = 1,000 元，一手 100 股 ⇒ **股价高于 10 元就一手都买不到**，`core/engine.py` 记为
  「资金不足或已达目标权重」并放弃（审计表 `run_backtest()["signals_rejected"]`）。
  实测（全区间 2016—2026、默认 `EngineConfig`、首笔权重 1%；把 9,313 条买入信号按代码与
  `trades`／`signals_rejected` 逐笔对齐后统计）：仅 2,369 条成交，约 **3/4 被拒**（其中首笔信号 5,239 条约 84% 被拒）
  ——早期汇报的「约 1/3」低估了该比例。
  `strategies/trend_card.py` 的 `n_tranches` 不能靠缩小 fraction 解决（首笔已到 1%），
  要缓解只能提高本金或放宽整手约束；后者属规则变更，须走规则变更单（`spec/09` 行 2166—2169）。

## 6. 验证协议与判定口径（摘要）

- 六维固定顺序（`spec/09` 行 2131）：历史回测 → 基准比较 → 交易成本（含全成本/零成本/成本×2）→ 参数敏感性 → 样本外 → 市场环境；
  缺数据的维度必须标注「不可完成」并给原因，不得静默跳过。
- 样本门槛：同一规则独立决策样本 ≥20 笔（行 2158/2183），不足则「样本不足，不得据此改规则」。
- 过拟合判定：阈值上下浮动后失效 → 过拟合嫌疑，降级或不采用（行 2131；`rules.sensitivity_grid`，V-01 用 ±2 个百分点）。
- 状态链：未验证 → 验证中 → 部分验证 → 已验证 → 已退役（行 2181—2182）；记录表固定 7 字段（行 2153）；
  规则文本改动走「规则变更单」（行 2166—2169）。
- 样本外切分：`config.IS_END=2023-12-31` / `OOS_START=2024-01-01`（行 2131⑤，切分须登记在记录表「数据区间」）。
- 市场环境分段：指数 250 日涨幅 >+15% 牛、<−15% 熊、其余震荡（行 2131⑥，标准须显式登记）。
